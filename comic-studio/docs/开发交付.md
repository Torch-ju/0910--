# 江湖写作助手 · 首版开发与验证

## 已实现的入口与核心模块

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 写作工作台 | `app/page.tsx`、`app/novel.css` | 世界、人物、节点、正文、章节记忆、修订与导出 |
| 漫画工作台 | `app/comic/page.tsx` | 保留原有漫画流程 |
| 存档接口 | `app/api/stories/route.ts` | 匿名身份、请求校验、任务入口、快照导出 |
| 故事模型 | `lib/story/model.ts` | 字段校验、状态结构、记忆事件重放、上下文选择及 Markdown 导出 |
| 工作流 | `lib/story/workflow.ts` | 世界/人物/主角/正文/章节/摘要的明确职责与确认门槛 |
| 模型适配 | `lib/story/ai.ts` | 固定 OpenAI 地址、结构校验、超时与一次结构修复 |

借鉴学习目录中的独立上下文、按需技能、分阶段任务和记忆索引思想；没有把教学用 Python harness 直接作为网页应用后端运行。

## 状态与恢复

- 计划与事实分离：确认世界、主角、节点是独立操作；确认事件方案不增加正文和事实。
- 正式正文、结构化剧本块和记忆变化在同一故事事务中提交。
- 每次操作携带故事版本和唯一请求 ID；重复成功请求返回存档，过期版本拒绝覆盖。
- D1 保存任务输入和阶段结果，但不保存 API Key。模型阶段失败后恢复已完成的检查点。
- 写锁默认 10 分钟，阶段完成后续期；超时结果不能覆盖新锁持有者。客户端收到失败后可恢复原请求。
- 章节整理不再次重写正文，只组织事件范围；摘要失败时章节阶段结果仍保存在任务 journal。正式章节列表在整次整理成功后更新，这与 PRD 的“章节先可见、摘要后更新”交互仍有差异。
- 角色卡、事实条目、伏笔和原始讨论独立保留；摘要返回的有效记忆 ID 必须完整，另做连续性检查。
- 重大修订的首版实现为明确的“从选定事件重新写”：保留旧快照，移出受影响下游正文，重放保留事件的记忆变化，作者重新构思。没有自动改写整个下游的能力。

- 6 项原漫画生成测试继续通过。

- 对本地真实 D1 / HTTP 接口验证：存档恢复、身份隔离、重复请求、过期版本、并发冲突、模型未配置时的锁释放、当前及历史导出。

## 当前边界

- 这是可运行首版，不是 PRD 全部 P0 条款均已完成验收。需要后续实测的部分包括文学质量、“不水剧情”、真实模型约束服从和长篇压力表现。
- 正文一次生成一个节点，最多 8 个场景；尚未实现同一节点跨多个模型调用的逐片段流式提交。
- 全文与历史快照采用 D1 JSON 存储。单故事状态保守限制约 1.7 MB，超限会要求导出并建立续篇；没有实现无限长篇对象存储。
- 上下文使用 UTF-8 字节作为保守上界，而非实际模型 tokenizer；独立正文 skill 也计入写作前预算检查。相关记忆当前完整载入，尚无向量检索。
- 普通叙事生成在结构输出不合法时修复一次；语义检查失败保留任务，用户重试时重新生成候选。
- 新增配角可以进入正文和事实记录；不会自动升级为正式可编辑主要角色卡。
- 人物与世界修订需要作者检查配角卡；不提供自动的依赖字段定位。
- 当前浏览器凭证为唯一匿名存档入口，没有账号登录、找回或跨设备同步。
- 局部候选改写需明确接受；当事实改变时拒绝按润色保存，需作者使用重大修订。
- 云端在线站点尚未发布，GitHub 仅为源码托管。

## DeepSeek 接入更新

写作工作台默认选择 DeepSeek（`deepseek-flash`），可切换原 OpenAI 配置。所有写作 Agent、章节归档和摘要使用同一服务；切换服务清空旧密钥，密钥仅存页面内存。后端只向固定官方域名发请求，保留旧 `x-openai-key` 请求兼容性。漫画工作台沿用原接口。

新增模型客户端合同测试覆盖服务路由、JSON 参数、空输出重试、截断和鉴权错误；合计 23 项测试、类型检查、生产构建通过。未提供真实 DeepSeek Key，尚未进行付费联调。
