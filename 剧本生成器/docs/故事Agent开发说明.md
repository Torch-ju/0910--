# 故事 Agent 开发说明

开发范围限定在 `./`，复用 FastAPI、SQLite/SQLAlchemy、Next.js 技术栈，无额外 Agent 框架。

## 产品约定

持续对话每轮生成可追溯摘要，混合消息按片段拆分。主线包含主角引导、世界观和故事线；辅助包含闲聊、情绪及偏好。闲聊可以影响剧情，但不能取代主角目标或覆盖已确认世界规则。将生活体验转成情节属于创作推定，需供用户审阅。

节点先待确认，支持编辑、重分类、版本历史、撤回和恢复。辅助节点在界面确认时默认允许影响剧情，用户可关闭。至少确认一个主角节点及另一主线节点才能成文。

## 实现

对话执行归类、摘要和引导；成文执行 Skill 加载、确认节点筛选、章节生成及连接校验。沿用持久化 Run、重试预算、取消和失败恢复。来源引文须存在于本轮原文；结构验证不能证明摘要语义完全准确，因此保留确认步骤。

新增 StoryNode、NodeRevision、StoryDraft 表和 0002 增量迁移。主辅线摘要分别进入有界上下文，全部节点与原文持久保存。最近窗口以外的摘要不自动检索；生成故事读取选定确认节点，超过预算提示用户缩减或调整预算。

成文加载本地 jin-yong-perspective 的创作原则摘录并记录完整文件 SHA-256。主线连接必须连通、无环并覆盖所有主线；选入的辅助节点必须在章节中引用且以 supports 指向主线，连接理由说明其影响。生成内容始终为待审阅草稿，未确认转折列入 assumptions。

编辑节点或资料会让旧故事过期。生成期间版本变化也会标记过期。修改使用乐观版本锁及幂等请求，来源不可修改，项目间节点隔离。

## 验证与限制

34 项后端测试通过，包括原有回归、主辅线拆分、确认与版本冲突、来源隔离、辅助选入影响、故事节点覆盖、循环/断连拒绝和旧稿失效。Ruff、前端 lint、类型检查、生产构建通过。

默认 mock 使用关键词分类和模板正文，仅验证流程。真实模型的长篇一致性、文学质量与语义分类仍待真实配置验收。第一版生成完整短篇草稿，不承诺一次生成无限长小说。

桌面 1280×900 与手机 390×844 的 6 项 Playwright 验收全部通过：含主辅线节点确认、辅助影响正文、来源查看、连接展示、故事导出及原有资料工作流。截图保存在 `frontend/test-results/desktop-agent.png` 与 `mobile-agent.png`，手机截图已人工查看。

## 对话区生成小说

输入框上方新增“生成小说”。点击时先取消当前回复任务，再读取最新版本并以 `use_summaries=true` 提交小说生成，自动进入故事结果页。保留“返回对话”入口。使用已保存的主线摘要及待确认辅助灵感；已确认但取消选入的辅助节点仍排除，撤回/过期节点排除。该操作不将待确认节点变成正式设定。未发送文字及中断前尚未产出的摘要不参与本次生成。仍需要一个主角节点及另一主线节点。

## 世界观与时间线问答优化

新增“开始问答引导”，按世界舞台、核心规则、势力冲突、主角目标、前史、开端、转折、高潮、结局共 9 个环节推进。用户可以跳选问题、重新回答、切回自由对话。问答摘要包含问题语境，短回答依问题归类为主线；节点撤回或过期后，该问题回到待回答状态。引导进度由当前有效节点恢复，刷新不丢失。

生成小说上下文包含问答索引，仅包含本次选入的摘要；依叙事阶段排序，真实模型需进一步根据用户表达的时间间隔检查因果和矛盾。当前模拟模式使用固定问题序列与问答摘录，不具备真实模型的语义追问或时间矛盾推理能力。用户回答“不知道”或有多处含混时的自适应追问由真实模型提示约束，尚待真实模型效果验收。

## 完整小说流水线（替代单次短篇生成）

真实模型的“连接节点生成故事”现在采用 Jin Yong Perspective Skill 的完整创作方法章节：六个心智模型、七条启发式、表达 DNA、张力、边界与速查表。用户决定与既有节点优先，排除冒充作者的角色扮演指令。

流程：完整情节蓝图 → 按章按场景写正文 → 持久化每段正文及连续性摘要 → 检查核心线索、结局与人物去向 → 对缺失章节及后续内容重写 → 保存完整故事。模型单次输出被截断时在原有重试预算内要求缩短本次片段，不通过压缩全书强行收尾。

取消总章节数 12 和单章 15000 字符上限，不设置小说总字数目标。单次模型响应仍受 STORY_OUTPUT_TOKENS 限制；累计付费请求受 MODEL_CALL_BUDGET 限制；单次上下文保守字节上限为 NOVEL_CONTEXT_BYTES（默认 180000）。超时、预算耗尽或失败会保留已写内容，不把半成品计入完整故事。

进度保存在 Run.context.novel_work，无需数据库迁移。GET `/projects/{pid}/novel-progress` 返回阶段与正文；POST `/projects/{pid}/novels/{rid}/resume` 从保存位置继续，已完成场景不重新生成。节点版本或模型变化时拒绝沿用旧上下文。每轮最多自动修订两次，仍未通过则保留修改意见等待继续写作；不是无限付费循环。

完整性判断结合结构覆盖、核心线索收束记录，以及模型对逐段摘要和正文结尾的审校。这不是对无限长全文的形式化证明，最终文学质量仍需用户阅读验收。模拟模式继续标记模拟模板，不能代表真实小说创作。

本轮验证：后端完整回归 45 项通过，新增输出截断重试测试单独通过；前端 lint、类型检查及生产构建通过，桌面/手机共 14 项浏览器验收通过，已查看手机写作进度截图。长篇分段测试覆盖 13 章、单章超过 15000 字符、完整性失败后修订以及失败续写不重复已保存场景。真实模型文学内容尚需实际生成后阅读评估。

## 每节长度调整

每节（页面中的一个章节）目标约 1200 字，验收范围 1000–1400 个非空白字符，含标点、不含标题。情节规划通过增加节数承载复杂内容，全书总字数不设限。单节写完后检查长度，超出范围由模型润色调整，保留事件因果与已收束线索，不进行机械截断；两次调整仍不合格则保存进度供继续写作。该规则用于新生成故事，已有历史稿件不自动改写。
