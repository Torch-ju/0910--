# 真实模型验收

本验收区分三件事：服务能返回文本、输出符合结构与业务校验、故事在语义和文学上可用。合成模型、离线测试和 HTTP 200 不能替代真实创作证据。

## 执行

在本地 `.env.local` 配置 LLM_BASE_URL、LLM_MODEL、LLM_API_KEY，运行 `npm run test:real`。默认验证武侠与魔幻：每种风格一次世界、一次人物、三轮剧情；每个模型输出最多一次结构修复，网络未知结果不自动重试。失败的设定链与使用受控初始设定的叙事链分别记录，不混同为完整世界生成成功。

结果写入独立的 `runtime/evaluation/<日期>/`，包括 report.json、ledger.json、世界/人物返回值与 stories。账本保留原始结构错误与对应响应、修复次数、耗时和服务报告的 token。未配置价格时费用为 null；缺 token 的尝试仍计数，但不能给出完整费用结论。该验收单独使用账本，不重置实际作品账本。

## 人工评审表

每种风格逐轮阅读实际正文与抽取日志，记录 PASS / FAIL / 待确认，并引用片段和证据 ID。

| 维度 | 应检查的事实 |
| --- | --- |
| 用户控制 | 用户只表达意图时，没有被写成自动成功；不替用户作下一步关键选择 |
| 身份与知识 | 不突然改名、增加重大能力或泄漏用户藏起的信件内容 |
| 时间与地点 | 叙事与转写位置相同；移动、时长有合理过渡 |
| 世界规则 | 武侠不擅自加入超自然力量；魔幻魔法遵守已确认的代价与限制 |
| 来源权威 | 角色自述、转述、推断不能自动升级为旁白事实或用户确认 |
| 伏笔 | 未解线索不混入已发生历史，已解决线索从摘要中退出 |
| 文学质量 | 段落衔接自然，避免重复台词与场景，无模板化收尾，留下行动空间 |
| 长期保持 | 回看第一轮关键事实；摘要遗漏时仍能从原始历史及证据恢复 |

不要仅靠关键字评分判定上述语义正确。脚本的 semanticReview 默认 PENDING，必须评审真实产出后才能改为有证据的结论。若需要调整提示词，保留旧报告，新版本重新运行，不覆盖失败记录。

## 显式恢复

使用 `REAL_EVALUATION_DIR=runtime/evaluation/<日期> node scripts/testing/recover-real.mjs` 仅恢复已有阻塞步骤，再补足至三轮；这会产生新的模型费用，保留独立 recovery 账本和报告。完整脚本优先使用生成并验证的世界/人物，受控设定回退会在报告单独标注。结构与业务错误共同进入最多一次修复。当前实际结果及人工评审见 LOCAL_ACCEPTANCE.md。
