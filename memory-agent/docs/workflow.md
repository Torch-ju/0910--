# 人物记忆 Agent 工作流

## 模块边界

上游情景演绎 Agent 负责生成剧情，本模块只分析已生成内容。输入小说文本即使包含命令式语句，也只能作为剧情证据，不能改变记忆 Agent 的运行规则。

每轮处理顺序如下：

1. 校验故事、章节、场景、轮次和请求 ID。
2. 使用 `storyId + requestId/turnId` 检查幂等。
3. 加载当前人物、确认别名、有效事实、近期事件和待解决冲突。
4. 调用可插拔抽取器，提取人物、事件、事实、关系和身份声明。
5. 使用稳定 ID、规范化名称和确认别名解析人物。
6. 只有旁白、明确身份揭示和用户确认可以自动合并人物。
7. 追加不可变事件和事实声明。
8. 动态状态按时间更新；静态事实发生冲突时保留双方并等待确认。
9. 自动纠错以追加纠正记录的方式执行，并生成用户通知。
10. 更新重要人物关系。
11. 为本章或本轮每个受影响人物生成最新完整画像快照，并生成各自不超过 100 字的核心摘要与跨章节动态轨迹。
12. 原子提交新记忆版本和本轮处理结果。
13. 后台异步生成向量，模型失败不回滚结构化事实。

## 证据权威级别

从高到低为：

1. 用户确认。
2. 明确身份揭示。
3. 小说旁白。
4. 人物自述。
5. 其他人物评价。
6. Agent 推断。

角色自述可能是谎言，不能用来自动合并伪装身份。Agent 推断必须带 `inference=true`、置信度和原文证据，不能伪装成旁白事实。

## 动态画像

画像采用三层记忆：

- 不可变事件记录：永不修改已经发生的剧情。
- 当前有效状态：由当前有效事实、关系和事件推导。
- 历史画像快照：每个版本均可追溯和回滚。

状态改变不会删除过去。例如人物早期保护无辜者、后期开始伤害无辜者，当前画像应同时表达早期表现和近期变化，而不是把人物简单改写成一个静态标签。

## 身份回溯

伪装人物在身份未揭示时使用独立的临时人物 ID。得到权威证据后：

- 临时人物记录标记为 `merged`，不物理删除。
- 伪装名称成为规范人物的确认别名。
- 过去事件、事实和关系转移到规范人物。
- 原章节当时的认知状态通过历史画像保留。

## 错误合并拆分

拆分必须由用户明确确认，并提供事件、事实、别名和关系端点的归属计划。无法确定归属的内容不应猜测，应留在当前人物或进入待确认流程。拆分后同时重建两个人物的完整画像，并写入新的记忆版本。

## 自动纠错

自动纠错只追加新事实，并把旧事实标记为 `superseded`。每次自动纠错都必须创建 `automatic_correction` 通知。静态事实出现同级旁白矛盾时，若抽取器不能确认是明确纠错，应创建冲突，不自动覆盖。
